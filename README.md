# XlsxDoctor

> 清理 Excel（`.xlsx` / `.xlsm`）文件内部累积的垃圾：**失效的定义名称**与**无人引用的外部链接**，让 Excel 打开速度恢复正常。

`C#` · `WinForms` · `.NET Framework 4.8` · 免安装单文件 exe · Windows

有些 Excel 文件"数据全删光了，体积却还有好几 MB，打开要等半天"。删除单元格数据只会清空工作表内容，而看不见的**失效定义名称**和**死外部链接**会一直累积在包里。XlsxDoctor 专门清理这两类垃圾——**逐条判定、绝不误删**，清理后所有单元格、公式、图表、格式与清理前完全一致。

## 功能特性

- **只删能证明是垃圾的东西，宁可不删**——只清理：① 值已失效（`#REF!` / `#N/A` 等）的定义名称；② 全工作簿没有任何公式 / 图表 / 条件格式 / 数据验证引用的定义名称；③ 没有任何公式引用的外部链接。
- **逐条引用分析**：识别全 Unicode 名称（含日文假名、西里尔文等非汉字字符）；保留定义名称的**完整依赖链**——被引用的名字所依赖的名字同样保留，杜绝清理后出现 `#NAME?`。
- **内容零改动**：工作表、图表、样式、共享字符串等部件**逐字节原样保留**，不重新序列化；只改写 `xl/workbook.xml`、`xl/_rels/workbook.xml.rels`、`[Content_Types].xml` 三个元数据文件。
- **双形态**：图形界面（拖放文件即可）+ 命令行（供批处理 / 脚本调用）。
- **免安装**：单文件 exe（约 320 KB），无需 .NET SDK、无需 Visual Studio、无需联网。
- **格式按内容识别**：OOXML 按 ZIP 签名识别、`.xls` 按 CFBF 签名识别，**不看扩展名**，与 Excel 自身的识别方式一致。
- **可复核**：附带独立无损验证脚本，用 Excel 真实打开两个文件逐格比对 + 强制全量重算。

## 快速开始

### 图形界面

1. 双击 `dist\XlsxDoctor.exe`，或直接把 `.xlsx` 文件拖到窗口上；
2. 工具自动分析并显示清理报告；
3. 点击 **「修复并保存」**，自动输出 `原文件名 - 已清理.xlsx`；
4. 原文件不被改动；若勾选"就地覆盖"，自动生成 `.bak` 备份。

### 命令行

```bat
XlsxDoctor-cli.exe 报表.xlsx
:: 生成 "报表 - 已清理.xlsx"

XlsxDoctor-cli.exe 报表.xlsx -o 清理后.xlsx
:: 指定输出文件

XlsxDoctor-cli.exe 报表.xlsx --dry-run
:: 只分析，不写任何文件

XlsxDoctor-cli.exe 报表.xlsx --conservative
:: 保守模式：只删"值已失效"的名称，其余一律保留

XlsxDoctor-cli.exe 报表.xlsx --in-place
:: 就地清理（自动备份 报表.xlsx.bak）
```

## 命令行参考

| 参数 | 说明 |
|---|---|
| `文件路径` | 要清理的文件（可多个；也可把文件拖放到 exe 图标上） |
| `-o, --out <路径>` | 指定输出文件（默认 `原名 - 已清理.xlsx`；仅限单文件） |
| `-i, --in-place` | 就地覆盖原文件（自动备份为 `.bak`） |
| `-c, --conservative` | 保守模式：只删值已失效的名称，其余一律保留 |
| `-n, --dry-run` | 只分析并输出报告，不写文件 |
| `--xls-info` / `--xls-repack` | `.xls` 引擎的诊断 / 重建命令（引擎默认关闭时无效，见"已知限制"） |
| `--cli` | 强制命令行模式（exe 被双击时默认进入图形界面） |
| `-h, --help` | 帮助 |

退出码：`0` 成功（含 `--help`）；`1` 内部 / 环境错误（罕见）；`2` 参数错误或文件不支持；`3` 清理后输出校验未通过（源文件不受影响）。

## 工作原理

### 清理对象与判定标准

| 垃圾类型 | 判定标准 | 为什么不影响结果 |
|---|---|---|
| 失效的定义名称 | 值本身就是 `#REF!` / `#N/A` 等错误标记 | 它指向的位置已不存在，引用它的公式本来就已经是错的 |
| 无人引用的定义名称 | 全工作簿的公式、图表、条件格式、数据验证中都找不到这个名字 | 没有任何地方用它，删除后计算结果不变 |
| 无人引用的外部链接 | 没有任何公式引用它 | 只是指向外部文件的死链接，还会拖慢打开速度 |

### 保留对象

- `_xlnm.*` 系统名称——打印区域、打印标题、自动筛选区域，删了打印设置就没了；
- 被公式引用的定义名称，以及它们**依赖链**上的全部名称；
- 被公式引用的外部链接（保留时报告会给出提示，并显示链接的真实目标路径）；
- 判定时字符串常量、单引号工作表名、单元格引用（`A1` / `$B$13`）、工作表限定符（`xxx!`）、内置函数名等会被正确排除，不会干扰判定——`SUM`、`Data`、`AN` 这类与函数名 / 工作表名 / 列号重名的名称都不会被误删。

### 三层安全网

1. **只写新文件**——默认输出 `原名 - 已清理.xlsx`，绝不碰原文件；
2. **写前差分校验**——输出包须通过 XML 可解析、关系可解析、Content_Types 完整等检查；发现问题时**回头校验源文件**，源文件自带的毛病不算工具的账（报告中标注"源文件自带，原样继承"），只有工具**自己引入**的新问题才会丢弃输出；
3. **就地覆盖自动备份**——`.bak` 与原文件逐字节相同。

校验器认得这些合法构造，不会误判：带片段的内部超链接（`Target="#Sheet1!A1"`）、`TargetMode="External"` 的外部关系、带 scheme 的绝对 URI（`http://`、`file://` 等）。

### 无损验证

`tests\Verify-NoLoss.ps1` 用 Excel 真实打开清理前后的两个文件，逐格比对**公式与计算结果**，并对清理后的文件做**强制全量重算**——若误删任何仍在使用的名称，对应单元格会立刻变成 `#NAME?`，逐格比对必然发现。实测一个 9.9 MB 的文件清理后（7.4 MB），48 万个单元格公式与数值逐格一致、强制重算零差异、错误值单元格数量不变。

## 已知限制

- **仅支持 OOXML 包**（`.xlsx` / `.xlsm` / `.xltx` / `.xltm`）；`.xlsb` 不支持。
- `.xls`（CFBF/OLE2 + BIFF8）的清理引擎**尚未完成开发**——此前测试中发现过缺陷，入口默认关闭（`FormatSniffer.XlsEnabled` 改为 `true` 重新编译可尝试启用，但**请勿用于真实数据**）。关闭时会给出明确提示并建议先"另存为" `.xlsx`。
- 只清理上述两类垃圾，不处理"多余单元格格式"、内嵌图片等其它体积来源。
- "是否被引用"采用穷举式文本判定，语义上偏保守——拿不准就保留。
- 清理不重算任何公式数值；外部链接只删除确认无人引用的。
